# Скриншоты отчёта по ЛР6 — обновлённое задание

План соответствует нумерации 1–16 из задания, присланного 03.11.2026.
Все пути к исходникам указаны относительно папки SDW-2026-Frontend.
Названия пунктов можно использовать как подписи рисунков.

## Перед началом

- Фронтенд запускается командой `npm run dev` в своей папке.
- Для mock-снимков остановите только Go-сервис (Ctrl+C в терминале его запуска).
  Vite должен продолжать работать; Docker-хранилища можно оставить запущенными.
- Используйте один origin: http://localhost:3000. Не меняйте его на 127.0.0.1:
  у другого origin отдельное localStorage.
- Откройте DevTools через F12. Для Redux установите расширение Redux DevTools.
- Для Network включите запись запросов; Preserve log сохраняет их при переходах
  и перезагрузке. Для AJAX выбирайте Fetch/XHR, для изображений — Img или All.
- Не включайте Offline в DevTools для mock-показа: по заданию выключен бэкенд,
  а не сам фронтенд.
- Для новой учебной базы вход: student / student123. Если пароль существующей
  записи был изменён, используйте свой действующий пароль.
- Страницу входа (рисунок 6) удобно снять перед входом для рисунков 3–5.

## 1. Плитка тарифов из mock-коллекции без бэкенда

1. Остановите Go-сервис.
2. Откройте http://localhost:3000/tariffs и нажмите F5.
3. Дождитесь карточек и надписи «Сервер недоступен. Демонстрационные тарифы».
4. Снимите карточки, фильтр и нижнее меню с пунктом «Вход».

Дополнительно в Network → Fetch/XHR можно выбрать /api/tariffs: ответ 503
в этом режиме ожидаем. Список отображается из TARIFFS_MOCK, не из API.

## 2. Лента тарифов из mock-коллекции без бэкенда

1. Не запуская Go, откройте http://localhost:3000/tariffs/feed.
2. Снимите название, описание, цену, RAM, видео/заглушку и подпись
   «Демонстрационные тарифы».
3. Лайки и добавление должны быть недоступны гостю.

## 3. Плитка тарифов из веб-сервиса

1. Запустите Go-сервис из папки своего бэкенда: `go run ./cmd/tariffs`.
2. Обновите /tariffs через F5. Возврат из ленты сам по себе не обновляет список.
3. Войдите в приложение и откройте плитку без ограничения цены.
4. Снимите реальные карточки, логин, «Выход» и крестики на своих тарифах.

Для подтверждения источника откройте Network → Fetch/XHR → tariffs → Response:
массив data поступает с бэкенда, признаки is_owner/is_liked вычислены сервером.

## 4. Лента тарифа из веб-сервиса

1. После входа откройте карточку на плитке.
2. Снимите видео, название, описание, цену, RAM и лайки.
3. Можно поставить лайк и показать изменившиеся сердце/счётчик.
4. Для демонстрации следующей карточки нажмите стрелку: в Network появится
   /api/tariffs/feed?id=<ID>&next=true.

## 5. Создание и публикация собственного тарифа

1. После входа нажмите «Добавление» (/tariffs/draft).
2. Если своего черновика нет, выберите фото и видео независимо, задайте название,
   нажмите «Далее».
3. Снимите загруженные медиа, статус «черновик», поля описания/цены/RAM и кнопку
   «Опубликовать». Если черновик уже есть, он загрузится сразу.
4. Для демонстрации выполните публикацию; новый тариф откроется в ленте.

В Network POST /api/tariffs → Payload видны multipart-поля tariff_name,
image и video. PUT /api/tariffs/<ID>/publication отправляет JSON описания,
цены и RAM. Для снимка достаточно читаемой формы второго шага; оба действия
можно дополнительно показать на защите.

## 6. Страница авторизации

1. До входа откройте http://localhost:3000/login.
2. Покажите поля логина/пароля, кнопку «Войти» и нижнюю навигацию.
3. Логин можно заполнить, пароль отображается точками.

Авторизованного пользователя /login перенаправляет на плитку. Поэтому этот кадр
удобнее снять до рисунка 3, сохранив его под номером 6. Либо выйдите и откройте
форму заново, затем снова войдите для следующих операций.

## 7. Изменение цены тарифа в PostgreSQL

1. Откройте http://localhost:8081 (Adminer).
2. Для штатной конфигурации: PostgreSQL; сервер postgres; пользователь cloud_user;
   пароль cloud_password; БД cloud_tariffs. При своей конфигурации используйте
   рабочие настройки ЛР4.
3. В таблице cloud_tariffs выберите опубликованный тариф, видимый на рисунке 3.
4. Измените price_per_month, например на 750, и сохраните.

Можно вместо редактирования строки выполнить SQL-запрос:

```sql
UPDATE cloud_tariffs
SET price_per_month = 750
WHERE tariff_id = 1
  AND tariff_status = 'опубликован'
RETURNING tariff_id, tariff_name, price_per_month;
```

ID 1 — пример. Подставьте ID выбранного опубликованного тарифа.
Снимите SQL и результат либо таблицу после сохранения: должны читаться ID,
название и новая цена.

## 8. Отображение изменения БД во фронтенде

1. Вернитесь на http://localhost:3000/tariffs и нажмите F5.
2. Найдите тот же тариф, проверьте цену 750 ₽ / месяц.
3. Снимите карточку с названием и новой ценой; сравните с рисунком 3.

Фильтр не должен исключать выбранный тариф. После F5 меню станет гостевым —
это специальное требование показа ЛР6. Для чтения опубликованных тарифов вход
не нужен. Отдельной кнопки обновления в приложении нет.

## 9. Переход в гостевое состояние Redux после F5 с сохранением JWT

1. Войдите. В меню виден «Выход».
2. Откройте Redux DevTools → State, посмотрите tariffUser:
   isAuthenticated=true, login заполнен, userId задан.
3. Нажмите F5, не нажимая «Выход».
4. Redux снова содержит isAuthenticated=false, login='', userId=0; меню показывает
   «Вход», добавление недоступно.
5. В DevTools откройте Application → Storage → Local Storage →
   http://localhost:3000. Выделите ключ cloud_tariffs_jwt: JWT остался.

Для основного кадра покажите одновременно гостевое меню и сохранённый JWT
в Application. Состояние Redux продемонстрируйте при защите. Если преподавателю
нужна фиксация обоих окон, можно сделать подпункты 9а (Redux) и 9б (Application).

В этом проекте JWT хранится в localStorage, не в сессионной cookie.
F5 не вызывает серверный logout: токен остаётся действительным до истечения
срока или явного отзыва. Автоматически к гостевым запросам он не добавляется.

## 10. JWT из Application в Postman/Insomnia и признак удаления

1. Не выполняйте выход после пункта 9: выход отзывает JWT.
2. Скопируйте полное значение cloud_tariffs_jwt из Application.
3. В Postman создайте GET http://localhost:8080/api/tariffs.
4. Authorization → Bearer Token: вставьте JWT в поле Token без слова Bearer.
5. Нажмите Send, в ответе data найдите собственный тариф.
6. Снимите метод/URL, настройку авторизации и фрагмент с user_id и is_owner=1.

В Insomnia аналогично задайте Bearer Token. is_owner=1 — признак для крестика
удаления. У чужого тарифа is_owner=0. Не используйте поле is_liked вместо него.
У вошедшего пользователя должен существовать опубликованный собственный тариф:
если его нет, сначала создайте и опубликуйте тариф через приложение.

## 11. Все состояния Redux Toolkit в коде

Откройте в редакторе следующие файлы:

| Файл | Что показать |
| --- | --- |
| src/store/tariffsSlice.ts | TariffsState и initialState: фильтры, items, feed, draft, источники данных, ID запросов, draftReady/listReady |
| src/store/userSlice.ts | initialState с isAuthenticated, login, userId; обычные actions входа/выхода |
| src/store/interfaceSlice.ts | pending и error; увеличение/уменьшение числа запросов |
| src/store/index.ts | configureStore: tariffs, tariffUser, tariffInterface |

Снимите начальные состояния рядом в группах редактора. Не уменьшайте шрифт
до нечитаемого: при необходимости используйте кадры 11а/11б в рамках этого
пункта. На защите также покажите эти три раздела в Redux DevTools.

Отдельно проверьте сброс фильтра: примените ограничение цены и нажмите «Выход».
В tariffs оба шага фильтра должны стать 0; на странице — «без ограничения».

## 12. Axios в кодогенерации и прямой Axios для авторизации

1. Откройте src/api/generated/TariffsApi.ts.
2. Найдите `import axios from "axios"` и `this.instance = axios.create(...)`.
3. В scripts/generate-api.mjs покажите параметр `httpClientType: 'axios'`.
4. Снимите сгенерированный файл и настройку генерации рядом в редакторе.

Для уточнённого условия авторизации дополнительно покажите в коде:

- src/api/index.ts: tariffUserHttp = axios.create(...).
- src/pages/LoginPage.tsx: await tariffUserHttp.post('/users/login', ...), затем
  dispatch(tariffUserLoggedIn(...)).
- src/components/TabBar.tsx: await tariffUserHttp.post('/users/logout', ...), затем
  dispatch(tariffUserLoggedOut()).

Это прямые Axios-запросы с ручным обновлением Redux обычными actions.
createAsyncThunk и сгенерированные методы users в этих обработчиках не вызываются.
Генератор обрабатывает полный Swagger и поэтому содержит также неиспользуемые
методы loginTariffUser/logoutTariffUser. Их наличие в файле не означает, что
вход/выход выполняются через кодогенерацию: реальные вызовы находятся выше.

## 13. Получение списка через сгенерированный клиент в thunk

1. Откройте src/store/tariffsSlice.ts, функцию getTariffs.
2. Покажите чтение appliedPriceStep через getState и передачу priceLimit:

```ts
const response = await tariffsApi.tariffs.getTariffs(
  limit ? { priceLimit: Number(limit) } : {}
);
```

3. Выше в том же файле покажите определение:

```ts
const tariffThunk = createAsyncThunk.withTypes<ThunkConfig>();
```

4. Рядом откройте сгенерированный getTariffs в src/api/generated/TariffsApi.ts:
   путь /tariffs, метод GET, query priceLimit.

Нужна связь «Redux thunk → сгенерированный Axios-метод». Имя getTariffs
соответствует теме. Обёртка tariffThunk является типизированным createAsyncThunk.
В extraReducers обработаны pending/fulfilled/rejected.

## 14. Создание и публикация через сгенерированные методы в thunk

1. В src/store/tariffsSlice.ts покажите createTariff и publishTariff.
2. В них видны вызовы tariffsApi.tariffs.createTariff(data) и
   tariffsApi.tariffs.publishTariff(id, fields).
3. Рядом можно открыть src/pages/DraftPage.tsx с dispatch(createTariff(...))
   и dispatch(publishTariff(...)), либо соответствующие методы generated-файла.
4. Снимите читаемые участки: компонент → dispatch → thunk → generated API.

Другие операции того же домена — getTariffFeed, getTariffDraft, deleteTariff,
setTariffLike — тоже реализованы через thunk и сгенерированный клиент.
Имена по теме задаются в scripts/generate-api.mjs. Если нужно показать сам
процесс кодогенерации, при работающем бэкенде выполните в папке фронтенда:

```bash
API_SCHEMA_URL=http://localhost:8080/swagger/doc.json npm run generate-api
```

Самостоятельный снимок генератора не заменяет пункты 13–14: преподаватель
просит именно применение сгенерированного кода внутри thunk.

## 15. AJAX через proxy фронтенда

1. Откройте /tariffs и Network → Fetch/XHR; очистите предыдущие запросы.
2. Выберите слайдером «до 1 000 ₽» и нажмите лупу.
3. Выберите tariffs?priceLimit=1000 → Headers.
4. Снимите Request URL, Request Method GET, Status Code 200 и query priceLimit.

Ожидаемый URL в браузере:

```text
http://localhost:3000/api/tariffs?priceLimit=1000
```

Именно порт 3000 подтверждает обращение к origin фронтенда. В vite.config.ts
маршрут /api перенаправлен на http://localhost:8080; фактический upstream
браузер не показывает. Настройку proxy можно открыть рядом с Network.

## 16. Имена и URL изображений из MinIO через S3 proxy

1. Используйте тариф с настоящим загруженным изображением. При необходимости
   создайте и опубликуйте свой тариф, загрузив фото через форму.
2. Откройте плитку, Network → All/Img и обновите страницу.
3. Найдите запрос, начинающийся с http://localhost:3000/s3/.
4. В Headers покажите успешный статус, имя бакета, имя файла и query подписи.

Пример браузерного URL (имя будет вашим):

```text
http://localhost:3000/s3/cloud-tariffs/image_....jpg?X-Amz-...
```

У запроса GET /api/tariffs → Response найдите эту же карточку и поля:

```json
{
  "image_name": "image_....jpg",
  "image_url": "http://localhost:9000/cloud-tariffs/image_....jpg?X-Amz-..."
}
```

Ответ API содержит подписанный адрес MinIO на порту 9000. Функция tariffMediaUrl
в src/api/index.ts заменяет его на /s3/..., а второй маршрут vite.config.ts
проксирует загрузку к MinIO. Исходные путь/подпись и Host сохраняются.
Для фиксации обоих представлений можно сделать 16а (Response с именем/URL)
и 16б (Headers запроса изображения).

/media/example.jpg — локальная заглушка, она не подтверждает загрузку из S3.
Если видна только заглушка, выберите тариф с реально загруженным файлом.

## Диаграмма, загрузка и контрольные вопросы

- Диаграмма прецедентов React находится в docs/UseCases_React_Lab6.drawio.
  Откройте её в draw.io и вставьте в соответствующий раздел отчёта отдельным
  рисунком: это требование к диаграммам, а не один из перечисленных 16 пунктов.
- Для показа Spinner в Network временно выберите Slow 3G и отправьте запрос
  фильтра. Пока идёт запрос, кнопки отключены, область интерфейса имеет inert.
  После демонстрации верните No throttling.
- Контрольные вопросы: Redux Toolkit (reducer, store, middleware), Axios,
  localStorage, CORS и обратный proxy, BFF/GraphQL, Next.js/SSG, FSD.
  BFF, GraphQL, Next.js и FSD перечислены в вопросах; внедрять их в проект
  вместо заданного стека только из-за этого перечня не требуется.
- Компоненты React функциональные. Классы сгенерированного HTTP-клиента
  не являются классовыми React-компонентами.
