# ЛР №5: установка и запуск на Fedora Linux

В архиве находится **только самостоятельный проект пятой лабораторной**.
Команды выполняются в его корне, где находятся `package.json` и `src`.
Карточки читаются из mock-коллекции; Go, PostgreSQL и MinIO не нужны.

Есть два независимых способа запуска. Можно выбрать один.

## 1. Что нужно установить

| Средство | Для чего нужно | Как устанавливается |
|---|---|---|
| Node.js | Выполнение инструментов разработки JavaScript | Пакет Fedora `nodejs` |
| npm | Установка библиотек проекта | Обычно устанавливается вместе с `nodejs` |
| TypeScript | Проверка типов и компиляция TS/TSX | Уже указан в `devDependencies`, устанавливается через `npm ci` |
| React и React DOM | Компоненты и вывод интерфейса в DOM | Через `npm ci` |
| React-Bootstrap и Bootstrap | Компоненты интерфейса и их базовые стили | Через `npm ci` |
| React Router DOM | Переходы между страницами SPA | Через `npm ci` |
| Vite и плагин React | Сервер разработки и сборка | Через `npm ci` |
| Docker и Compose v2 | Альтернативный запуск в контейнере | Docker уже установлен; проверить `docker compose version` |

JavaScript не нужно устанавливать отдельным пакетом «языка» — он выполняется
браузером и Node.js. TypeScript, React и остальные библиотеки устанавливаются
локально в проект; глобальная установка через `sudo npm install -g` не нужна.
Go, Python и Java для работы SPA не требуются.

## 2. Способ А: запуск через Node.js

### Шаг 1. Установить Node.js и распаковщик

```bash
sudo dnf install nodejs unzip
node --version
npm --version
```

В Fedora npm обычно входит в установку Node.js. Если команда `npm` отсутствует:

```bash
sudo dnf install npm
```

Нужен Node.js **22.12 или новее в ветке 22**, либо **24 или новее**.
Проект проверен с Node.js 24.22.1. Если установлен старый Node.js,
обновите пакет и проверьте версию:

```bash
sudo dnf upgrade nodejs
node --version
```

Если репозитории вашей версии Fedora всё ещё предоставляют старую ветку,
можно использовать способ Б с `node:24-alpine` внутри Docker — системный
Node.js тогда не нужен.

### Шаг 2. Распаковать архив

Ниже предполагается, что архив находится в `~/Downloads`.
Если каталог загрузок называется иначе, замените путь к ZIP.

```bash
mkdir -p ~/Projects/lab5
unzip ~/Downloads/SDW-2026-Lab5-React.zip -d ~/Projects/lab5
cd ~/Projects/lab5/SDW-2026-Lab5-React
```

Все последующие npm-команды выполняйте **в этой папке**, где лежит `package.json`.

### Шаг 3. Установить все библиотеки

```bash
npm ci
```

Команда установит React, React DOM, React-Bootstrap, Bootstrap,
React Router DOM, TypeScript, Vite, плагин React и пакеты типов.
Версии зафиксированы в `package-lock.json`. Интернет нужен для первоначальной
загрузки зависимостей, но не для получения карточек.

Отдельно устанавливать каждый пакет не требуется. Для понимания состава
проекта соответствующие группы команд выглядят так:

```bash
# Библиотеки, используемые приложением (уже перечислены в package.json):
npm install react react-dom react-bootstrap bootstrap react-router-dom

# Инструменты разработки (уже перечислены в package.json):
npm install -D typescript vite @vitejs/plugin-react @types/react @types/react-dom @types/node
```

Для готового архива используйте именно **`npm ci`**, а не повторную установку
групп выше: это сохраняет проверенные версии. `@types/react-router-dom`
не нужен: современный React Router содержит собственные типы.

### Шаг 4. Запустить приложение

```bash
npm run dev
```

Терминал остаётся занят сервером. В браузере откройте:

```text
http://localhost:3000
```

Появится плитка тарифов. Изменения в TSX/CSS автоматически применяются через
Vite. Остановить сервер: **Ctrl+C** в терминале. Для повторного запуска:

```bash
cd ~/Projects/lab5/SDW-2026-Lab5-React
npm run dev
```

Повторять `npm ci` каждый раз не требуется.

### Шаг 5. Проверить сборку

После остановки сервера либо во втором терминале:

```bash
npm run typecheck
npm run build
```

`build` тоже включает проверку TypeScript, затем создаёт `dist`.
Для просмотра готовой сборки остановите dev-сервер на порту 3000 и выполните:

```bash
npm run preview
```

Адрес снова <http://localhost:3000>. Остановка — Ctrl+C.
Не открывайте `dist/index.html` двойным щелчком: SPA требуется HTTP-сервер.

## 3. Способ Б: через уже установленный Docker

На хосте для этого способа **не нужны Node.js, npm или TypeScript** —
Docker установит их в образе. Распакуйте ZIP по шагу 2 выше и откройте корень распакованного проекта.

### Шаг 1. Проверить Docker и Compose

```bash
docker --version
docker compose version
docker info
```

Если установлен Docker Engine, но демон не запущен:

```bash
sudo systemctl enable --now docker
```

Если установлен именно Docker Desktop, запускайте Desktop обычным способом.
Если Docker Engine доступен только с правами root, используйте
`sudo docker compose ...` последовательно для команд ниже.

### Шаг 2. Собрать и запустить

```bash
cd ~/Projects/lab5/SDW-2026-Lab5-React
docker compose up --build
```

При первом запуске загрузится `node:24-alpine`, установятся зависимости и
запустится Vite. Откройте <http://localhost:3000>.
Во втором терминале выполните `docker compose ps`; должен отображаться проброс `127.0.0.1:3000->3000/tcp`.
У frontend нет зависимостей от серверов предыдущих лабораторных.

Bind mount содержит `:Z`, чтобы SELinux в Fedora разрешал контейнеру читать
каталог проекта. Зависимости контейнера хранятся в отдельном Docker volume.
Vite использует polling, поэтому редактирование исходников на хосте
автоматически обновляет приложение в контейнере.

Остановка: Ctrl+C, затем при необходимости:

```bash
docker compose down
```

Или запуск в фоне:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f frontend
```

Ctrl+C после `logs -f` закрывает просмотр журнала, но не останавливает контейнер.
При следующем запуске без изменения Dockerfile достаточно:

```bash
docker compose up -d
```

Если изменились `package.json` или `package-lock.json`, выполните:

```bash
docker compose build frontend
docker compose run --rm frontend npm ci
docker compose up -d
```

Обычный запуск контейнера больше не повторяет установку зависимостей.

## 4. Что проверить перед сдачей

1. На плитке четыре карточки; поля берутся из `src/modules/mock.ts`.
2. Слайдер меняет максимальную цену, лупа применяет фильтр.
   При ограничении 1 000 ₽ остаются две карточки.
3. Карточка Yandex открывает ленту с `id=2` и стандартным видео.
4. В ленте работают «ещё…», «свернуть» и стрелка следующего тарифа.
   RAM и число лайков находятся под соответствующими иконками.
5. Внизу четыре пункта; только лента и плитка доступны.
6. Для проверки заготовки третьей страницы вручную откройте
   <http://localhost:3000/tariffs/draft>. В меню она не используется.
7. Обновление страницы и прямые ссылки работают.
8. `npm run build` завершается без ошибок.

Полное описание всех страниц, кнопок и полей — в `README.md`.

## 5. Возможные проблемы

**`ENOENT ... package.json`.** Открыта не та папка. Перейдите в `SDW-2026-Lab5-React`, где лежит `package.json`.

**`EBADENGINE`, старая версия Node.js.** Проверьте `node --version` и
`which node`. Используйте подходящую версию или Docker со встроенным Node.js 24.

**Порт 3000 уже занят.** Остановите ранее запущенный сервер Ctrl+C или
контейнер `docker compose down` в соответствующей папке.
Для локального Node-запуска можно выбрать другой порт:

```bash
npm run dev -- --port 3001
```

Тогда адрес — `http://localhost:3001`. Для Docker измените только левую часть
проброса на `127.0.0.1:3001:3000` в `docker-compose.yml` и выполните
`docker compose up -d --build`.

**`Cannot connect to the Docker daemon`.** Запустите Docker Engine или Desktop.

**`Permission denied` на Docker socket.** Для текущего запуска используйте
`sudo docker compose ...`; не меняйте права сокета командой `chmod 777`.

**Не удаётся загрузить библиотеки или Docker image.** При первой установке
нужен интернет. После восстановления соединения повторите ту же команду.

**На странице стандартная картинка с крестом.** Это предусмотренный
`example.jpg` из предыдущего проекта, а не ошибка приложения. Для Yandex
она специально используется из-за пустого `image_url`.

**Не открывается другой компьютер по адресу сервера.** Compose намеренно
публикует порт только на локальном компьютере. Для выполнения работы
открывайте `localhost:3000` на машине с приложением; изменение firewall
и открытие портов в сеть для локальной работы не нужны.

## Если npm ci выполняется долго

В этом архиве добавлен `.npmrc` с использованием кэша, отключением
автоматического audit и проверки обновления npm, а также ограничением
времени ожидания сетевых запросов. Первый запуск скачивает отсутствующие
пакеты; последующие установки используют кэш npm. Не очищайте кэш командой
`npm cache clean --force`: после неё придётся скачивать всё заново.

После успешной установки повторять `npm ci` при каждом запуске не нужно:

```bash
npm run dev
```

Чтобы увидеть, на каком запросе задержка, используйте:

```bash
npm ci --loglevel=http
```

Если появляется `ETIMEDOUT`, `ECONNRESET` или ошибка DNS, это проблема
соединения с реестром пакетов; настройки проекта не могут увеличить скорость
самого соединения. Официальный реестр: `https://registry.npmjs.org/`.
Ограничение времени в этом проекте позволяет получить конкретную ошибку,
а не ждать завершения зависшего запроса несколько минут.


В `package.json` закреплена версия `@react-aria/ssr` 3.9.10 в зависимости
`@restart/ui`. Она удовлетворяет диапазону, требуемому React-Bootstrap,
но не подтягивает полные пакеты `react-aria` и `react-stately` (около 50 МБ
в распакованном виде), которые появились в новой ветке этой утилиты.
Состав компонентов и их поведение сохранены. Версии установки зафиксированы
в обновлённом `package-lock.json`.
