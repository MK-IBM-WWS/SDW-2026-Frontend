# Дополнительная лабораторная: Tauri + CLIP

## 1. Бэкенд

Распакуйте архивы рядом, чтобы получились `frontend/` и `backend/`.

```bash
cd backend
docker compose up -d postgres minio redis adminer
go run ./cmd/migrate
go run ./cmd/seed-clip
go run ./cmd/tariffs
```

Сохранён `.env` из исходного проекта. API слушает `0.0.0.0:8080`, PostgreSQL — порт `666`, MinIO — `9000`, Adminer — `8081`.
Скрипт seed-clip добавляет ровно 100 новых опубликованных тарифов облачного распознавания изображений: десять категорий × десять планов. Английские описания длиной 50–100 символов. Повторный запуск пропускает существующие записи по исходному имени и сохраняет правки цены/описания. Не запускайте старый `cmd/seed`: он создаёт набор для лабораторной по индексам.

Тестовые фото уже лежат в `backend/test-images/`. Скрипт загрузит их, если папка отсутствует, и поместит изображения в MinIO. Существующие тарифы и медиа сохраняются.

На компьютере сервера определите адрес сетевого интерфейса:

```bash
ip -4 -br address
```

Выберите IP Wi-Fi/Ethernet, доступный клиенту, например `192.168.1.50`. Не выбирайте `127.0.0.1`, docker0 или адрес другого интерфейса. На сервере разрешите API в активной зоне firewalld:

```bash
sudo firewall-cmd --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp
```

Если сервер и клиент находятся на одном ПК, всё равно используйте его LAN IP. Если backend в виртуальной машине, IP должен быть доступен клиенту (обычно нужен сетевой мост).

## 2. Собрать и запустить настоящее Tauri-приложение

Подставьте **свой IP сервера**, не копируйте пример без изменения:

```bash
cd ../frontend
bash scripts/build-fedora.sh 10.133.98.180

```

Скрипт устанавливает npm-зависимости без ненужной загрузки CUDA, согласует IP в коде, CSP и разрешениях HTTP-плагина, проверяет/загружает локальный CLIP и собирает release + RPM. Для npm/Cargo нужен Интернет; модель и WASM включены в архив. Первый запуск скрипта может занимать несколько минут. Минимум для комфортной сборки: 8 ГБ RAM и около 8 ГБ свободного диска; отдельная видеокарта не требуется. Модель запускается локально на CPU в WASM worker.

После сборки Vite и Node не нужны для работы запущенного приложения. Бэкенд должен продолжать работать.
RPM находится в `src-tauri/target/release/bundle/rpm/`; можно установить его командой `sudo dnf install ./src-tauri/target/release/bundle/rpm/ИМЯ_ПАКЕТА.rpm`.
Если нужен только исполняемый файл:

```bash
npm run tauri build -- --no-bundle
```

После смены сети/IP пересоберите приложение:

```bash
npm run native:configure -- 192.168.1.50
npm run tauri build -- --no-bundle
```

Значение по умолчанию `192.168.1.100` — шаблон, а не автоматически найденный сервер. Адрес указан в `src/native/target_config.json`; служебного подвала в интерфейсе нет. Backend и Tauri могут работать на разных компьютерах.

Для разработки: `npm run tauri dev`. Режим `npm run native:dev`/`native:preview` в браузере использует обычный fetch и требует разрешить его Origin в `CORS_ORIGINS` на backend. Это не требуется для собранного Tauri, где API вызывается через Rust HTTP-плагин.

## 3. Проверка функции поиска

1. Запустите release-файл. На плитке отображаются все опубликованные услуги с обычной пагинацией. Служебных фильтров по префиксу CLIP нет.
2. Вместо слайдера цены расположен поиск. Введите название тарифа и нажмите прежнюю голубую кнопку с лупой. Для поиска по фото нажмите соседнюю кнопку выбора файла, выберите `backend/test-images/tiger.jpg`, очистите название и нажмите лупу. Крестик на превью сбрасывает фото.
3. При поиске по фото должны отображаться тарифы `CLIP-tiger-*`. Используются все опубликованные услуги с подходящими английскими описаниями, включая обычные записи без префикса CLIP.
4. Откройте карточку стрелкой или нажатием на неё. «Подробнее» оформлена как лента 7-й лабы: изображение, название, описание с «ещё…», цена, RAM, счётчик лайков и прежняя кнопка перехода. Нижняя панель содержит только две доступные гостю страницы — «Лента» и «Плитка». Изменять лайки гость не может.
5. Вернитесь на плитку — запрос, фото и страница сохраняются. Данные плитки и открытой карточки автоматически запрашиваются раз в 15 секунд. Кнопок обновления нет. Фоновый опрос не перекрывает интерфейс индикатором загрузки.

Параметры CLIP фиксированы в `src/native/search.ts`: порог **0,60**, TopK **10**.
Порог применяется к согласованной шкале `(cosine + 1) / 2`. Значения, векторы,
оценки и настройки модели не выводятся в интерфейсе.

Почему 0,60 и 10: на десяти фотографиях тестового набора 100/100 нужных тарифов найдены,
macro Precision/Recall/F1 = 1,0. Пороги 0,4/0,5 с TopK 10 тоже сработали, но 0,60 лучше
отсекает слабые совпадения. TopK 3/5 теряет часть десяти подходящих планов; 20 может
включать другие категории. От 0,70 совпадения на этих фото исчезают. Это калибровка
на иллюстрациях набора, не независимая оценка качества. Замеры: `docs/clip-calibration.*`.

Для повторной калибровки используйте терминал:

```bash
node scripts/calibrate-clip.mjs ../backend
# Собственные фото с именами cat.jpg, dog.jpg, horse.jpg, tiger.jpg,
# elephant.jpg, bird.jpg, car.jpg, bicycle.jpg, flower.jpg, football.jpg:
node scripts/calibrate-clip.mjs ../backend /путь/к/фото docs/my-calibration
```

Модель сравнивает загруженное фото с английскими описаниями, а не с картинками карточек.
Услуги с русскими/неподходящими по длине описаниями остаются в обычной плитке, но не участвуют
в поиске CLIP. Подробности: `src/native/search.worker.ts` и `src/native/search.ts`.
