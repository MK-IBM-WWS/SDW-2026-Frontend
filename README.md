# Лабораторная работа №5 — базовое SPA на React

Тема: **тарифы облачного хостинга**. React + TypeScript + Vite,
React-Bootstrap и React Router. Оформление перенесено из HTML-страниц
предыдущей лабораторной: колонка 390 px, тёмный фон, голубые элементы,
двухколоночная плитка, полноэкранная видеолента и нижняя навигация.

По согласованному варианту задания карточки получают данные **только из
`src/modules/mock.ts`**. Бэкенд, PostgreSQL и MinIO для этой работы не нужны.
В коде SPA нет `fetch`, Axios, Redux, `createContext`, `useContext` или
`useOutletContext`. Общая коллекция хранится в `App` и передаётся через props.
Все компоненты функциональные. Встроенные механизмы React Router и
React-Bootstrap используются обычным способом; собственного Context нет.

## Быстрый запуск

Нужны Node.js 22.12+ из ветки 22 или Node.js 24+ и npm.
Из **корня распакованного проекта**, где находится `package.json`:

```bash
npm ci
npm run dev
```

Адрес: <http://localhost:3000>. Подробная установка на Fedora,
объяснение библиотек и запуск через Docker: **`FEDORA.md`**.

Альтернативный запуск из того же каталога:

```bash
docker compose up --build
```

Открывается тот же адрес. Конфигурация предназначена для локальной разработки.
Порт 3000 опубликован на хосте, а не только внутри контейнера.
Сервис слушает `0.0.0.0:3000`, и `:Z` у bind mount учитывает SELinux в Fedora.
В архиве находится только самостоятельный проект пятой лабораторной.

## Страницы и элементы интерфейса

| Страница | Адрес | Поля и содержимое | Кнопки и поведение |
|---|---|---|---|
| Плитка | `/tariffs` | Заголовок «Тарифы», слайдер максимальной цены, карточки с фото, названием, ценой и количеством лайков | Голубая кнопка с лупой применяет фильтр; карточка открывает выбранный тариф в ленте |
| Лента | `/tariffs/feed`, `/tariffs/feed?id=2` | Видео, название, краткое/полное описание, цена; справа иконки RAM и лайков, значения под ними | «ещё…»/«свернуть» раскрывает описание; стрелка показывает следующий опубликованный тариф; лайк гостю недоступен |
| Черновик, заготовка | `/tariffs/draft` | Сначала фото и видео друг под другом с выбором файлов, затем название; после «Далее» — описание, цена и RAM | «Далее» проверяет обязательные поля и открывает редактирование параметров; «Опубликовать» отключена. Эта страница не участвует в гостевом сценарии и открывается только вручную по адресу |

`/` перенаправляет на плитку. Неизвестный путь или отсутствующий/неверный `id`
показывает сообщение и ссылку возврата. По умолчанию лента открывает первый
опубликованный тариф; после последнего стрелка снова открывает первый.
Прямая ссылка и обновление страницы работают через Vite.

### Нижняя навигация

| Пункт | Состояние | Действие |
|---|---|---|
| Лента | Доступен | Переход на `/tariffs/feed` |
| Добавление | Недоступен (`disabled`) | Перехода нет |
| Плитка | Доступен | Переход на `/tariffs` |
| Вход | Недоступен (`disabled`) | Перехода нет |

Панель закреплена внизу колонки, активная вкладка выделена.
Сердце в ленте показывает количество лайков, но не изменяет его:
авторизация в этой работе не реализуется.

### Фильтрация

Сохранены четыре положения слайдера из предыдущей работы:
без ограничения, до 1 000 ₽, до 10 000 ₽, до 500 000 ₽.
Перемещение меняет подпись; **список меняется только после нажатия лупы**.
Фильтрация выполняется в памяти условием `price_per_month <= priceLimit`.
Применённое значение отражается в URL, например `/tariffs?priceLimit=1000`.
Снятие ограничения убирает параметр. Кнопки браузера «Назад» и «Вперёд»
восстанавливают применённый фильтр. Неизвестное значение параметра
трактуется как отсутствие ограничения.

### Данные и стандартные медиа

`TARIFFS_MOCK` содержит четыре опубликованных тарифа, черновик и удалённую
запись. `getPublishedTariffs()` отбирает только опубликованные записи для
обоих гостевых экранов. Ни HTML-шаблоны Go, ни API источником карточек не являются.

В `public/media` лежат собственные файлы приложения:

- `example.jpg` — изображение по умолчанию;
- `example.mp4` — видео по умолчанию;
- изображения AWS, Azure и Google и видео AWS из приложенного проекта.

У `Yandex Cloud Pro` **оба медиа-поля пустые**: это готовый пример проверки
стандартных файлов. У Azure и Google пустое поле видео. При пустом или
состоящем из пробелов URL выбирается стандартный файл; ошибка загрузки
непустого URL также переключает компонент на стандартный файл.
Повторной бесконечной попытки загрузить отсутствующий стандартный файл нет.
Видео в ленте воспроизводится без звука, автоматически и по кругу.
Все медиа и CSS локальные; после установки зависимостей интернет для
просмотра карточек не нужен.

Черновик — только заготовка: выбранные файлы используются через
`URL.createObjectURL`, не загружаются на сервер и освобождаются через
`URL.revokeObjectURL` при замене или уходе со страницы. После «Далее» выбор
файлов скрывается, фото и видео остаются видимыми. При уходе со страницы
или обновлении черновик сбрасывается. Коллекцию карточек он не изменяет.

## Структура исходников

```text
src/
  main.tsx                   # Bootstrap CSS, StrictMode, BrowserRouter
  App.tsx                    # общая коллекция и маршруты
  types/tariff.ts             # тип объекта тарифа
  modules/mock.ts             # все данные карточек
  modules/priceFilter.ts      # положения слайдера, формат цены
  hooks/usePageTitle.ts       # эффект смены заголовка вкладки
  hooks/useObjectUrl.ts       # эффект создания и освобождения URL файла
  components/
    TabBar.tsx               # Navbar с четырьмя пунктами
    PriceFilter.tsx           # Form.Range и Button
    TariffCard.tsx            # Card и ссылка в ленту
    TariffImage.tsx           # изображение со стандартным файлом
    TariffVideo.tsx           # видео со стандартным файлом
    Icon.tsx                 # SVG-иконки интерфейса
  pages/
    TilesPage.tsx             # плитка и применение фильтра
    FeedPage.tsx              # текущая карточка и переход к следующей
    DraftPage.tsx             # неиспользуемая в меню заготовка черновика
  styles.css                 # адаптация оформления предыдущей работы
public/
  images/                    # фон и иконка RAM
  media/                     # фото и видео, включая стандартные
```

`useState` хранит состояние, обработчики событий меняют его,
`useEffect` синхронизирует слайдер с URL, меняет заголовок вкладки и управляет
временем жизни локальных URL файлов. `key={tariff_id}` при смене карточки
сбрасывает раскрытие описания и состояние видео. Переходы через `Link` и
`NavLink` не перезагружают документ. `Card`, `Button`, `Form`, `Form.Range`,
`Form.Control` и `Navbar` взяты из React-Bootstrap.

## Соответствие методичке 5MAN.md

Использованы Vite, React/TS, маршрутизация, функциональные компоненты,
props, состояние и эффекты, разбиение на компоненты, mock-коллекция,
локальные стандартные медиа, нижняя панель и Docker с hot reload.

Уточнения задания имеют приоритет над общим примером iTunes:

1. Собственный бэкенд не подключается: выбран вариант **только mock**.
   Поэтому для SPA не нужны proxy, настройка CORS или расширения браузера.
2. В панели четыре пункта, доступны два. Третья страница — заготовка
   черновика по прямому адресу, согласно уточнению задания.
3. Данные передаются через props. Пример методички с `useOutletContext`
   не используется из-за запрета Context.
4. Типы React Router уже входят в `react-router-dom`. Устаревший отдельный
   пакет `@types/react-router-dom` не устанавливается.

## Проверка вручную

1. Открыть `/tariffs`: четыре опубликованные карточки; нет `Legacy Hosting`
   и `Selectel Start`.
2. Сдвинуть слайдер на «до 1 000 ₽»: до нажатия лупы карточек ещё четыре.
   Нажать лупу: останутся AWS за 400 ₽ и Yandex за 600 ₽; в URL —
   `priceLimit=1000`. Положение «без ограничения» и лупа вернут четыре.
3. Открыть карточку Yandex: URL содержит `id=2`, видны стандартные фото/видео.
   Развернуть описание и нажать стрелку: откроется Azure со свёрнутым описанием.
4. Пройти стрелкой все тарифы: после Google снова AWS.
5. Проверить доступность двух вкладок, отсутствие переходов по «Добавление»
   и «Вход», выделение активной вкладки.
6. Открыть вручную `/tariffs/draft`: проверить форму; выбрать фото и видео,
   задать название, нажать «Далее». Появятся описание, цена и RAM;
   фото/видео останутся, повторного выбора и публикации нет.
7. Проверить ширину 390 и 320 px в инструментах разработчика и обычное окно
   ПК: горизонтальной прокрутки быть не должно, панель остаётся внизу.
8. В DevTools → Network нет обращений к `/api`, MinIO или внешним сервисам.
   При навигации внутри SPA не появляется новая загрузка типа Document.
9. Открыть `/tariffs/feed?id=999`: сообщение об отсутствующем тарифе.
10. Выполнить `npm run build`: проверка TypeScript и production-сборка.

## Команды

```bash
npm ci              # установка точных версий из package-lock.json
npm run dev         # разработка, порт 3000, hot reload
npm run typecheck   # проверка TypeScript
npm run build       # проверка TypeScript и сборка в dist/
npm run preview     # просмотр предварительно выполненной сборки на порту 3000
```

Для размещения production-сборки на другом HTTP-сервере требуется SPA fallback
на `index.html`, чтобы прямые ссылки `/tariffs/feed` не возвращали 404.
Для обычного запуска работы достаточно Vite или приложенного Docker Compose.

## Установка зависимостей

`npm ci` выполняется один раз после распаковки, а затем — при изменении
`package-lock.json`. Для обычного повторного запуска достаточно `npm run dev`.
В проект добавлен `.npmrc`: npm использует имеющийся кэш без проверки его
устаревания, не запускает автоматический audit и проверку обновления самого npm.
Целостность пакетов по `package-lock.json` продолжает проверяться.
Отсутствующие пакеты по-прежнему скачиваются: первый запуск зависит от сети.

Зависший HTTP-запрос ограничен 60 секундами и одной повторной попыткой.
Это позволяет получить сообщение об ошибке соединения вместо многоминутного
ожидания; такая настройка не ускоряет медленное интернет-соединение.
При необходимости подробного журнала используйте `npm ci --loglevel=http`.
Для отдельной проверки зависимостей можно выполнить `npm audit` вручную.

В Docker зависимости устанавливаются при сборке образа. При обычном запуске
контейнера повторная установка больше не выполняется.
При изменении зависимостей обновите образ и содержимое тома:

```bash
docker compose build frontend
docker compose run --rm frontend npm ci
docker compose up -d
```


В `package.json` закреплена версия `@react-aria/ssr` 3.9.10 в зависимости
`@restart/ui`. Она удовлетворяет диапазону, требуемому React-Bootstrap,
но не подтягивает полные пакеты `react-aria` и `react-stately` (около 50 МБ
в распакованном виде), которые появились в новой ветке этой утилиты.
Состав компонентов и их поведение сохранены. Версии установки зафиксированы
в обновлённом `package-lock.json`.
