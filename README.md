# Индексы в БД

React + TypeScript + React-Bootstrap + Redux Toolkit/thunk + Axios с кодогенерацией.

## Запуск

Нужен Node.js 22.12+ либо 24+.
Сначала запустить контейнеры, миграцию, генератор и Go API
Затем из этой папки:

```bash
npm ci
npm run dev
```

Открыть http://localhost:3000 . Учебный вход новой БД: `student` / `student123`.
Vite проксирует `/api` к `http://localhost:8080`, а `/s3` — к `http://localhost:9000`.
Если адреса другие, создать `.env.local`:

```dotenv
API_TARGET=http://localhost:8080
S3_TARGET=http://localhost:9000
```

После изменения этих переменных перезапустить Vite.
Остановка: Ctrl+C. Бэкенд должен работать одновременно с Vite.

## Что добавлено

- Плитка получает по 10 карточек с бэкенда. В Redux хранятся `currentPage`, `pageSize`, `total`, `totalPages`, фильтр и сведения о времени запроса.
- `page` и `limit` уходят в API вместе с `priceLimit`; пагинация содержит первую/последнюю, предыдущую/следующую страницы и только несколько соседних номеров, поэтому 12000 страниц не создают 12000 кнопок.
- Применение нового фильтра цены сбрасывает страницу на первую. Само движение слайдера не отправляет запрос. Повторное нажатие лупы повторяет запрос с текущими параметрами.
- Над плиткой показано только число найденных тарифов. Номер страницы, размер выдачи, время запросов и состояние индекса в этом блоке не отображаются. Время и состояние индекса остаются в ответе API и Redux для проверки через Network/Redux DevTools. Команды включения/отключения индекса находятся в README бэкенда; перезапуск приложения не нужен.
- Лента из 100 карточек формируется в Redis сразу при загрузке приложения, даже если сначала открыта плитка. Запрос `init=true` сохраняет уже созданный набор при повторном обращении. Cookie `feed_session` передаётся браузером, логин для этого не требуется.
- Плашка с номером карточки, позицией в сотне и текстом «Карточка из списка» скрыта. Нумерация сохраняется в Redis и ответе API: после №100 идут №101..200, затем №201..300. ID внутри каждой сотни уникальны. Между разными сотнями возможны совпадения.
- Состав/порядок сотни берутся из Redis. Лайки и статус карточки проверяются сервером по БД. Вошедший пользователь получает свою ленту и может ставить/снимать лайки.
- После создания/удаления тарифа список запрашивается заново с ограничением размера страницы. Переход по карточке из плитки и прежние экраны входа/черновика сохранены.

Если Go API не запущен, гостю доступны прежние моковые карточки, теперь тоже с локальной пагинацией. В этом режиме нет настоящих времён запросов и Redis. Ошибка Redis от работающего API отображается как ошибка, без подмены ленты моками.

После F5 Redux снова гостевой, как в ЛР6. Копия JWT остаётся в localStorage для демонстрации, но не используется автоматически для входа. Cookie ленты сохраняет гостевую сессию отдельно от JWT.

## API и сборка

Swagger-схема в `src/api/swagger.json` и клиент `src/api/generated/TariffsApi.ts` обновлены. Они включены в архив — для обычного запуска генерация не нужна.

```bash
npm run generate-api
npm run build
```

При необходимости получить схему с работающего Go API:

```bash
API_SCHEMA_URL=http://localhost:8080/swagger/doc.json npm run generate-api
```

Список: `/api/tariffs?page=1&limit=10&priceLimit=1000`.
Лента: `/api/tariffs/feed?init=true`, затем `/api/tariffs/feed?position=2` и т.д.
`data` списка по-прежнему массив; метаданные страницы находятся рядом с ним: `total/page/limit/query_ms/index_enabled`.
Метаданные ленты находятся в `feed`: `redis_key`, `batch_id`, `batch_start`, `batch_size`, `position`, `session_id`.

Результат `npm run build` находится в `dist`. Для разработки и демонстрации используйте `npm run dev`: в нём настроен прокси к Go/MinIO. При отдельной публикации `dist` потребуется прокси в веб-сервере.
